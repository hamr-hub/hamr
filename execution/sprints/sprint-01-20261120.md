## 目标与成功标准

1. 先让管家核心链路可重复验证，再开放给家庭成员使用。当前环境只允许模拟模型，不部署、不运行 Ollama 或其他真实模型。模拟模型验证协议、数据、审批与会话；真实推理质量单列，等待另行授权的环境，不转用云端。
2. 让跨仓库门禁检验主仓库实际锁定的版本。文档引用损坏、端口契约漂移应直接失败，而不是被跳过。
3. 把未完成项拆成有退出条件的阶段。区分「代码已落地」「本地已验收」「远程 CI 已通过」「线上已验证」。

### 尚未完成与原因

| 项 | 状态 | 原因 |
|----|------|------|
| 真实模型工具遵循度、延迟与准确率 | 未验收 | 当前环境不运行真实模型，且不自动转云端；需另行授权的环境 |
| 成员级会话隔离与审批主体鉴权 | 未实现 | 现有 `member_id` 来自客户端请求，缺少可信身份来源；须先定服务端身份与权限矩阵 |
| 三个仓库的托管 CI 首次转绿 | 修复中 | 推送后首轮 CI 暴露三类失败（clippy 新 lint、sqlx 与 Rust 1.100 不兼容、私有子模块克隆不到），本地已用 CI 同款工具链修复并验证，等远端复跑确认 |
| 私有子模块在 CI 中的指针新鲜度 | 未覆盖 | `repos/hamr-mood-calender` 是 private 仓库，GITHUB_TOKEN 无权克隆；已按跳过清单降级为警告，需给根仓配置 `HAMR_CROSS_REPO_TOKEN` 才能恢复完整校验 |
| 网关与账号、JiaBu 的身份映射 | 未修 | 账号 token 的 `sub` 是用户 ID，JiaBu 当作家庭 ID 使用；需要跨服务协议决策，不宜单方面改 |
| 状态页真实指标、Compose 路径与备份恢复 | 未验证 | 需隔离环境演练；线上拓扑与 DNS 只在获得授权的只读核实后确认 |

## 风险与阻碍

| 风险 | 处理方式 |
|------|----------|
| 本地模型只答不查或忽略结果 | 用固定合成事实同时断言工具调用、答案内容；体检通过不代表 20–30 题质量基线达标 |
| 本地信任模式与多成员隔离不是一回事 | 先定义成员标识的可信来源和服务端权限矩阵；未通过负向用例前不把家庭 Agent 暴露给不互信的成员 |
| 根仓库记录的是 gitlink，不是子模块工作区 | 子模块改动先在其仓库发布与验证，再同步根仓库指针；不把未跟踪文件或未发布改动纳入发布证据 |
| 线上拓扑和代码目录可能不一致 | 以授权的只读现场证据核对，不根据仓库命名推断部署，不在本轮改 DNS 或重启服务 |

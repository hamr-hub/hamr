# Cluster 3: Go Core Services — Optimization Report
Date: 2026-06-30
Scope: hamr-account, hamr-api, hamr-status

## Executive Summary

- **Three Go 1.22 services in v0.1/0.2** share no Go module today even though they all live under `github.com/hamr/*`; each ships its own HTTP server bootstrap, logger config, env-loader, and Helm chart scaffolding — substantial duplication and an obvious extraction target (`internal/pkg` or `hamr-go-kit`).
- **Security posture has serious gaps**: CORS in `hamr-api/cors.go:34` short-circuits on a literal `"*"` entry allowing any origin with credentials; `hamr-api/auth.go:24-29` leaks Hydra's introspection error strings to clients; `hamr-status/main.go:112-128` does N+1 lookups against Postgres with no context-timeout discipline; `hamr-account/cmd/login-app/main.go:152-174` ships **TODO stubs** for `/api/register` and `/api/login` returning fake success — a P0 trust defect.
- **Reliability tooling is thin but not absent**: `hamr-api/middleware/breaker.go` provides gobreaker middleware but is **never wired into the router** (see `hamr-api/cmd/api/main.go:60-71`); graceful shutdown exists in all three services, but there's no readiness probe on `hamr-account/login-app`, no liveness on `hamr-status/health`, and no Prometheus instrumentation for the actual `cmd/login-app/main.go` (only `/health` text body).
- **Observability is partial**: `hamr-api` has `promhttp` mounted at `/metrics` and uses `zap`; `hamr-status` has a hand-rolled Prometheus text-format handler that's missing several standard fields (`HELP`/`TYPE` lines); `hamr-account/login-app` uses bare `log.Printf` and has no structured logging, no request IDs, no metrics. None of the three use OpenTelemetry, trace propagation, or `slog`.
- **Testing is shallow**: zero integration tests, no fuzzing, no race-detector CI invocation; `tests/*.go` files live outside any package (just use `package tests` + cwd copy in `scripts/smoke.sh`), so `go test` won't actually compile them in-place — they're effectively dead unless someone wires a root-package wrapper. Coverage is unclear because no test is wired into the build.

## Per-repo findings

### hamr-account

- [P0] **[security] Login handlers are unstubs that always return 200 OK** — `cmd/login-app/main.go:146-169` — `registerHandler`, `loginHandler`, `enable2FAHandler` ship `TODO: 转发到 Kratos/Hydra` markers and instead write `{"status": "ok", "message": "登录成功 (mock)"}`. Anyone hitting `/api/login` with any email/password is "authenticated". This is a critical auth bypass; ship-blocker for v0.1. — **effort: M** — **impact: high**
- [P0] **[reliability] No graceful-shutdown drain for the `go` goroutines / no readiness/liveness probe on login-app** — `cmd/login-app/main.go:43-92` — `httpServer` sets `ReadHeaderTimeout` but no `ReadTimeout`/`WriteTimeout`/`IdleTimeout`; chart `charts/templates/login-app.yaml:30-34` declares only `readinessProbe`, no `livenessProbe` (the Kratos/Hydra templates do have one — inconsistent). If upstream Hydra is down, the pod will keep reporting ready. — **effort: XS** — **impact: high**
- [P0] **[security] Argument passed to Sscanf parses user-controlled header bytes safely but `verify` blindly trusts** — `internal/auth/argon2.go:77-91` — uses `fmt.Sscanf` to read m/t/p params, then uses them as `uint32` directly with no upper bound; an attacker who can inject a stored hash can set `Memory=0` to make verification microseconds (the decoded hash parameter overrides `DefaultParams`). Switch to manual scanner + tight bounds. — **effort: S** — **impact: med**

### hamr-api

- [P0] **[security] CORS `isAllowed` returns true for literal `"*"` then sets `Access-Control-Allow-Credentials: true`** — `internal/middleware/cors.go:32-39` — This is the textbook CVE-class: with `Access-Control-Allow-Origin: *` plus credentials, browsers reject the response, but the server still processed the request. More importantly, if a config file mistakenly enables `*` it disables the Same-Origin protection. Refuse `"*"` outright when credentials are on. — **effort: XS** — **impact: high**
- [P0] **[perf] `Breaker` middleware is declared but never registered** — `internal/middleware/breaker.go:13` and `cmd/api/main.go:60-71` — the routes loop adds only `Auth` + `proxy.New`, no `middleware.Breaker`. With 12 backends, this means a single hung hamr-deploy can starve an api pod's goroutines. Either wire it or remove it (and the runbook lying about its existence). — **effort: S** — **impact: high**
- [P0] **[security] OAuth2 introspection error is reflected verbatim to caller** — `internal/middleware/auth.go:24-29` — `"introspection failed: " + err.Error()` exposes downstream URLs (e.g. `hydra:4445`), credentials leak via the introspector error chain, and gives reconnaissance value. Log internally, return generic 502. — **effort: XS** — **impact: high**
- [P0] **[reliability] Route `/v1/api` recursive proxy → `http://localhost:8080` causes an infinite loop on internal errors** — `configs/routes.yaml:16-19` and `cmd/api/main.go:69-71` — `routeGroup.Any("/*proxyPath", handlers...)` means the api routes itself, recursively. Add an explicit deny-list or a circuit-breaker around the route. — **effort: S** — **impact: high**
- [P1] **[perf] Token introspection cache has no upper bound — unbounded growth** — `internal/auth/introspect.go:33-37, 99-103` — `map[string]cachedClaims` grows with every unique token; a flood (or compromised client emitting many tokens) is a memory leak. Add a `maxSize` LRU or periodic eviction goroutine. — **effort: S** — **impact: med**
- [P1] **[perf] `Introspector.cache` is mutated under `sync.RWMutex` but the read path holds the lock while doing a `time.Now()` check — needless lock contention** — `internal/auth/introspect.go:59-64` — micro-optimization but trivial. Alternative: use `sync.Map` or an LRU. — **effort: XS** — **impact: low**
- [P1] **[security] `cfg.Hydra.ClientSecret` supports `${VAR}` substitution but only at top-level fields, not nested in `routes` list** — `internal/config/config.go:50-66` — backend URLs/secrets in routes cannot be templated. Document this limitation or generalise. — **effort: XS** — **impact: low**
- [P1] **[reliability] Redis client uses `PoolSize: 20` with no `MinIdleConns`** — `internal/ratelimit/redis_store.go:22-31` — cold-start penalty on first request. Add `MinIdleConns: 5`. — **effort: XS** — **impact: low**
- [P1] **[perf] `ChainRateLimits` issues sequential Redis round-trips for global→ip→user** — `internal/middleware/ratelimit_redis.go:60-83` — adds 3 latency hits per request. Either skip the `global` layer or collapse with a single Lua script. — **effort: M** — **impact: med**
- [P1] **[testing] `_ = strconv.Itoa` and `var _ = limiter.Rate{}` are dead-code "quiet" assignments** — `cmd/api/main.go:124` and `internal/ratelimit/redis_store.go:147` — sign that some imports aren't actually used; remove or fix imports. — **effort: XS** — **impact: low**
- [P1] **[observability] No request-ID propagation, no `traceparent` header pass-through** — repo-wide — when the gateway forwards to backends, traces cannot be stitched. Add `propagation.TraceContext` (OTel) or `X-Request-ID` middleware. — **effort: S** — **impact: med**
- [P1] **[security] `cfg.Redis.Password` and `cfg.Hydra.ClientSecret` are expanded once at load time — no rotation support** — `internal/config/config.go:50-66` — for secret rotation, add a SIGHUP handler. — **effort: S** — **impact: med**
- [P2] **[perf] Default timeouts are inconsistent with what `proxy.New` would expect** — `configs/routes.yaml:1-73` — some routes have `timeout: 30s` but the http.Server `WriteTimeout` defaults to 30s too — a slow backend response will hit the http.Server write timeout *before* the route timeout. Document the contract. — **effort: XS** — **impact: low**
- [P2] **[perf] `httputil.NewSingleHostReverseProxy` uses default Transport (no connection pooling tuned)** — `internal/proxy/proxy.go:22` — Provide a per-backend Transport (or one shared) with `MaxIdleConns=100`, `MaxIdleConnsPerHost=20`, `IdleConnTimeout=90s`. — **effort: XS** — **impact: med**
- [P2] **[security] No request body size limit; `proxy-read-timeout: "30"` annotation but no body-size limit** — `charts/templates/deployment.yaml:83` — Add `LimitBodySize` middleware or rely on `nginx.ingress.../proxy-body-size: "10m"`. — **effort: XS** — **impact: low**
- [P2] **[security] Wildcard `*.hamr.top` origin matcher strips trailing dots wrongly** — `internal/middleware/cors.go:32-48` — `strings.Split(pattern, "?")[0]` looks like a leftover from query-string handling but the strings have already been stripped. - [P2] **[dx] No OpenAPI spec generation from routes** — `configs/routes.yaml` — README promises "OpenAPI 3.1 聚合文档" but no generator. Add `oapi-codegen` or similar to emit `/openapi.json` and `/docs`. — **effort: M** — **impact: med**

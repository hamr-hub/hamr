# Cluster 1: Astro Frontends — Optimization Report
Date: 2026-06-30

Scope: `repos/hamr-website`, `repos/hamr-docs`, `repos/hamr-help`
Method: Read-only deep audit of `package.json`, `astro.config.mjs`, `Dockerfile`, `nginx.conf`, `charts/values.yaml`, `README.md`, `public/`, `src/`, `scripts/`, and cross-repo `diff`.

## Executive Summary
- All three repos duplicate Astro/Bootstrap/nginx scaffolding almost verbatim; a single shared `@hamr/astro-config` package could collapse ~150 lines per repo.
- Security posture is uneven: only `hamr-website/nginx.conf` has `X-Frame-Options` + `Referrer-Policy`; **none** have HSTS, CSP, or `Permissions-Policy`. `hamr-help/src/layouts/BaseLayout.astro:38-39` loads Bootstrap + Mermaid from `cdn.jsdelivr.net` at runtime — a third-party-CDN supply-chain risk.
- SEO is roughly OK on `hamr-website` (OG/Twitter/sitemap) but **broken** on `hamr-help` (no OG, no sitemap, no `<link rel="canonical">`); `hamr-docs` only emits sitemap for its own pages and the Redocly HTML at `/api/` bypasses the sitemap entirely.
- CI/testing is thin: only `hamr-docs` has any GitHub Actions workflow (`.github/workflows/aggregate-openapi.yaml`); zero unit/E2E tests across all three; no `lint`, `format`, or `type-check` script in any `package.json`.
- Build assets are correct but unhardened: full `bootstrap.min.css` (~230KB) is imported on every page even though only a subset of utility classes is used; CDN scripts in `hamr-help` are not preloaded/async-deferred and break Astro's "0 JS by default" claim.

## Per-repo findings

### hamr-website
- [P1] **Build/Perf** Bootstrap CSS is imported wholesale — `src/layouts/BaseLayout.astro:3` imports the full `bootstrap/dist/css/bootstrap.min.css` (~230KB) on every page; pages only use a handful of grid + utility classes. Replace with `bootstrap/scss/bootstrap-grid.scss` + a tiny custom layer, or tree-shake via PurgeCSS. — **Effort: S** — **Impact: high** (LCP, TTFI, CLS).
- [P1] **Build/Perf** Full `bootstrap-icons` (~120KB WOFF + CSS) imported in `BaseLayout.astro:4` even though only 13 icons are used (`FeatureGrid.astro:4-17` defines the list). Use the `@astrojs/icon` sprite or self-host only the subset. — **Effort: S** — **Impact: high**.
- [P1] **SEO** Missing `<link rel="canonical">`, no `hreflang` alternates, no JSON-LD structured data — `src/layouts/BaseLayout.astro:22-43`. The repo declares "结构化数据 (v0.2)" in `docs/architecture.md:38` but it's never implemented. Add Organization + WebSite + Product schemas and `rel=canonical` (especially with the planned i18n). — **Effort: S** — **Impact: high**.
- [P1] **i18n** Astro `i18n` is configured (`astro.config.mjs:13-16`) but no `src/pages/en/` content exists; the README claims "中文 + 英文双语" but only Chinese content is shipped. Either ship `/en/` pages or remove the claim. — **Effort: M** — **Impact: med** (ranking/trust signal).
- [P1] **Security** `Dockerfile:13` pulls `nginx:1.27-alpine` (`:latest` tag implicit) — pin to a digest and use a `nginxinc/nginx-unprivileged` variant. `EXPOSE 80` should be paired with `USER nginx` and a read-only filesystem. — **Effort: XS** — **Impact: med**.
- [P1] **Security** Nginx missing HSTS, CSP, `Permissions-Policy`, COOP/CORP — `nginx.conf:25-29`. Add `Strict-Transport-Security "max-age=31536000; includeSubDomains"`, a strict CSP (`default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`), and `Permissions-Policy: camera=(), microphone=(), geolocation=()`. — **Effort: S** — **Impact: high**.
- [P1] **SEO** `ogImage = '/og-image.png'` default in `BaseLayout.astro:18` references a file that does not exist in `public/`. Will produce a 404 in social previews. Either ship a 1200x630 PNG or use the favicon SVG. — **Effort: XS** — **Impact: high**.
- [P2] **Accessibility** `<nav>` lacks `aria-label` in `src/components/Header.astro:4`; the toggler button has no `aria-controls`/`aria-expanded`. Bootstrap's collapse JS requires these for screen readers. — **Effort: XS** — **Impact: med**.
- [P2] **DX** `package.json:6-12` has no `lint`, `format`, `type-check`, or `test` script; no `eslint`, `prettier`, or `vitest` in `devDependencies` (`package.json:20-22`). Add `astro check`, `eslint-plugin-astro`, and `prettier-plugin-astro`. — **Effort: S** — **Impact: med**.
- [P2] **DX** No CI workflow under `.github/` (directory absent). Add a `.github/workflows/ci.yaml` running `npm ci && npm run build && bash scripts/smoke.sh` on PR + push. — **Effort: S** — **Impact: med**.
- [P2] **Observability** No analytics, no RUM, no error tracking. Adding privacy-friendly Plausible (`https://plausible.hamr.top`) or self-hosted Umami is a 2-line script tag. — **Effort: XS** — **Impact: med**.
- [P2] **SEO** `public/robots.txt` exists but `charts/values.yaml:10` declares the host as `hamr.top`; no per-environment `noindex` staging or `meta robots` controls. Add a build-time `process.env.PUBLIC_NOINDEX` injection in `BaseLayout.astro`. — **Effort: XS** — **Impact: low**.
- [P2] **Performance** Hero uses emoji (`🏠`, `🏡`) at 200px (`Hero.astro:8,18`) which renders inconsistently across OSes and tanks CLS on Linux/Android. Replace with inline SVG. — **Effort: XS** — **Impact: med**.
- [P2] **Accessibility** Color tokens `--hamr-primary` and `--hamr-secondary` (`src/styles/global.css:3-4`) fail WCAG AA on white text in `Hero.astro` / `features.astro` gradient (#667eea ~ 4.18:1 on white passes AA for large text but the gradient mixes with #764ba2 — measure both). — **Effort: XS** — **Impact: med**.
- [P2] **DX** `tsconfig.json:2-8` extends `astro/tsconfigs/strict` and defines `@/*` alias, but no source file uses `@/` imports — either adopt them repo-wide or remove the alias. — **Effort: XS** — **Impact: low**.
- [P2] **Deploy** `charts/values.yaml:11-12` resource limits `{cpu: 100m, memory: 128Mi}` are reasonable for nginx static but no `livenessProbe`/`readinessProbe` is configured — only the `HEALTHCHECK` (`Dockerfile:19`) which doesn't translate to K8s probes. Add probe definitions to values.yaml. — **Effort: XS** — **Impact: med**.
- [P2] **Deploy** No image-tag pinning in `charts/values.yaml:2` (`tag: latest`). ArgoCD will pick up silent rebuilds. Switch to immutable `v0.1.0` tags + ImageUpdater. — **Effort: XS** — **Impact: med**.

### hamr-docs
- [P0] **SEO/Build** The Dockerfile's Redocly stage (`Dockerfile:9-13`) re-uses `/app/src/api/unified.openapi.yaml` from the builder, but `scripts/aggregate.sh:55` writes to `src/api/unified.openapi.yaml` from CI, not from the Dockerfile build. The Docker build never re-aggregates — it just renders the **committed** seed file. The cron job (`aggregate-openapi.yaml:6`) refreshes the source every 6 hours but a Docker build on tag-push uses stale data. Add `RUN bash scripts/aggregate.sh --render` between builder → redocly stages, or run aggregation in CI and copy the artifact in. — **Effort: M** — **Impact: high**.
- [P0] **Build** `scripts/aggregate.py:39-50` logs `⚠️` for path/schema collisions but then silently overrides (`unified_paths[path] = methods`, `unified_schemas[name] = schema`). Two services exposing `/oauth2/token` will overwrite each other with no abort. Switch to prefix-namespacing (`/account/oauth2/token`) or fail-on-conflict. — **Effort: S** — **Impact: high**.
- [P1] **Build** `Dockerfile:12` uses `redocly/cli:latest` (mutable). Pin to a digest (`@redocly/cli@1.25.11` or similar) for reproducible builds. — **Effort: XS** — **Impact: high**.
- [P1] **Performance** Mermaid is loaded from a CDN in `src/layouts/BaseLayout.astro:39` (`https://cdn.jsdelivr.net/npm/mermaid@10/dist/mermaid.min.js`, ~700KB minified) on **every page** even when no diagram is rendered (e.g. `getting-started.md` has no Mermaid). The `<Mermaid>` component itself (`src/components/Mermaid.astro:1-8`) just renders a `<div>` placeholder — Mermaid is not actually invoked via the component, only via a single global `<script>mermaid.initialize(...)` on every page. — **Effort: M** — **Impact: high**.
- [P1] **Security** `BaseLayout.astro:38-39` imports Bootstrap JS + Mermaid JS from `cdn.jsdelivr.net`. No SRI hash, no CSP. Either self-host and add `integrity` attributes, or scope the CSP to allow the CDN explicitly. — **Effort: S** — **Impact: high**.
- [P1] **Security** `nginx.conf:10` only sets `X-Content-Type-Options: nosniff`. Missing X-Frame-Options, Referrer-Policy, HSTS, CSP (especially important for docs.hamr.top because the Redocly HTML iframe would be blocked by frame-ancestors). — **Effort: S** — **Impact: high**.
- [P1] **DX** `scripts/aggregate.py:33-50` is not invoked in `scripts/aggregate.sh` until line 55 (after the `cd`); the shell script imports `python3 scripts/aggregate.py` but `python3` is not declared as a dependency in any Dockerfile. `node:20-alpine` ships without `python3` — `Dockerfile` builds will fail if anyone adds the aggregation step. — **Effort: XS** — **Impact: high**.
- [P1] **SEO** Redocly HTML output at `/api/index.html` is **not registered** in the sitemap; `@astrojs/sitemap` (`astro.config.mjs:3,8`) only walks `src/pages/`. Add a custom `serialize` callback or add a route stub. — **Effort: S** — **Impact: med**.
- [P1] **SEO** `BaseLayout.astro:13` uses `<title>{title} | HamR Docs</title>` but emits no OG, no Twitter, no canonical. Same fix as hamr-website. — **Effort: S** — **Impact: med**.
- [P2] **DX** `package.json:5-9` has no `lint`/`format`/`test` scripts; same as hamr-website. — **Effort: S** — **Impact: med**.
- [P2] **DX** No `tsconfig.json` (file does not exist in repo) — Astro defaults to `base: strict` only when present. Add one. — **Effort: XS** — **Impact: med**.
- [P2] **SEO** No `public/robots.txt`. Add one (mirrors hamr-website/robots.txt with the docs.hamr.top sitemap URL). — **Effort: XS** — **Impact: med**.
- [P2] **DX** `redocly-cli.yaml:23-24` enables `bundle.extends: recommended` but no `apis.unified.openapi.yaml` is referenced as input to `bundle` — the config declares a bundle that isn't invoked by `aggregate.sh` (which uses `python3 aggregate.py`). - [P2] **DX** `.github/workflows/aggregate-openapi.yaml:22` runs `bash scripts/aggregate.sh --render` on schedule, but there's no separate CI workflow that builds/tests the Astro site on PR. ## Cross-repo opportunities
- **Shared `@hamr/astro-config` package.** All three `astro.config.mjs` files share: `output: 'static'`, `vite.ssr.noExternal: ['bootstrap']`, `@astrojs/mdx` integration, and the same site URL pattern (`https://{host}.hamr.top`). Extract to `repos/hamr-ui` or `repos/hamr-infra` as `packages/astro-config/index.mjs` and `extends` from each repo. Saves ~10 lines per repo and unifies build flags.
- **Shared `nginx.conf`.** Three near-identical configs; only `hamr-website` has the full security-header set (X-Frame-Options, Referrer-Policy) and `Cache-Control: immutable`. Hoist the hardened `hamr-website` version to a shared chart template `repos/hamr-infra/charts/static-nginx/templates/conf.yaml` and parameterize the `server_name`. Estimated ~50 LOC reduction per repo.
- **Shared `Dockerfile`.** `hamr-website` and `hamr-help` Dockerfiles are functionally identical (Astro build → nginx serve). Extract to `repos/hamr-infra/docker/astro-static.Dockerfile` and `ARG SITE_URL`. `hamr-docs` adds a Redocly stage — use a separate `astro-docs.Dockerfile` or layer it on top via `COPY --from=...`.
- **Shared design tokens + components.** `.bg-gradient-primary` (`#667eea → #764ba2`), `.hover-lift`, `Header`/`Footer` patterns, `BaseLayout` boilerplate are duplicated across all three repos. Create `repos/hamr-ui` with: `<BrandHeader>`, `<BrandFooter>`, `<GradientHero>`, `<HoverCard>`, and a `tokens.css` with `--hamr-*` variables. Can be consumed via npm workspace (`"@hamr/ui": "workspace:*"`) once a monorepo or pnpm workspace exists.
- **Shared `smoke.sh`.** Three near-identical smoke scripts (file existence + JSON parse + grep for frontmatter). Generalize to a single `repos/hamr-infra/scripts/smoke-static-site.sh` accepting the expected file list as args.
- **Shared CI workflow.** Only `hamr-docs` has any workflow. Create `repos/hamr-infra/.github/workflows/astro-static-build.yaml` (reusable workflow) called by each site's `.github/workflows/ci.yaml` for: `npm ci`, `npm run build`, `bash scripts/smoke.sh`, `docker build`, push to ghcr.
- **SEO/i18n strategy.** Only `hamr-website` declares Astro's `i18n`; none actually ship the second locale. A shared `i18n.ts` content collection with `defaultLocale: 'zh-CN'` and a 1-page `/en/` stub per site is a quick win for the SEO play.
- **Structured data (JSON-LD).** None of the three layouts emit JSON-LD. Could share a `<OrganizationJsonLd>` / `<ProductJsonLd>` Astro component in `hamr-ui`.
- **OpenAPI rendering decoupling.** Currently the OpenAPI aggregation runs only in `hamr-docs`. The unified spec could live in `repos/hamr-api/contracts/` and `hamr-docs` would consume it as a build input — making the contract source-of-truth clearer and the docs build idempotent.

3. **Extract `@hamr/astro-config` + shared `nginx.conf` + shared `Dockerfile`** to `repos/hamr-infra` and consume from all three repos. Highest ROI: removes ~50 LOC of drift and unblocks upgrading Astro / patching nginx CVEs in one place. — **Effort: M** — **Impact: high**.
4. **Add security headers + CSP + SRI to all three nginx.conf files**, plus switch CDN scripts in `hamr-help` and `hamr-docs` to self-hosted. One nginx config + SRI attributes = 1 PR per repo. — **Effort: S** — **Impact: high**.

Combined with fixing the `hamr-website` `og-image.png` 404 and adding missing OG/sitemap to `hamr-help` and `hamr-docs`, this closes the SEO/security baseline gap and makes further changes safe. — **Effort: M** — **Impact: high**.

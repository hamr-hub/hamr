# Cluster 4: Go Tools / Agents — Optimization Report
Date: 2026-06-30

## Executive Summary
- All three repos share the same `gin + distroless + port 8080` skeleton — the biggest near-term win is a shared `internal/` package for env loading, graceful shutdown, JSON error envelopes, and Prometheus metrics; right now each repo reimplements these with subtle divergence (no metrics at all in deploy/jiabu, masked-URL logs, fake promhttp).
- Production-critical logic is currently stubbed: `argocd.Sync` returns no real K8s error, `argocd.GetRolloutStatus` always returns `"Healthy"` (orchestrator.go:169), `monitorRollout` is a 10-minute blind poll that never aborts, `precheck.Check` allows `prod` deploys unconditionally, and `jiabu` keeps all events in process-local memory (`handlers/events.go:24`). These are P0 correctness/safety issues, not nice-to-haves.
- `mood-calender` has a real bug in `Weekly()` (`trends.go:36`) — `d.Date[:7]` returns `YYYY-MM`, not an ISO week, so per-week aggregation is wrong; `Insights` then compares two consecutive *months* but labels the comparison "本周/较上周". This is the loudest agent-quality regression on the cluster and it's shipped to `main`.
- DX is uniformly thin: no `Makefile`/`Taskfile`, no CI workflows (`.github/workflows` absent in all three), no structured logging, no tracing, no real auth middleware, no tests for orchestrator/deploy/sync critical paths, and no retry/timeout config on outbound HTTP in `notifier`/`argocd`.
- Security/Privacy posture has a paper ↔ code gap: `PRIVACY.md` claims raw `content` is "默认丢弃", but the code only discards when a non-existent gin context key (`"privacy-store-content"`) is set — by default content *is* kept in-memory forever (`events.go:65-67`). Likewise `ARGOCD_TOKEN` is logged indirectly via env reads and ready to be leaked through `monitorRollout` HTTP errors.

## Per-repo findings

### hamr-deploy
- [P0] **Reliability** Deploy orchestrator polls Argo Rollouts with a hardcoded 10-min loop that always reports success — `internal/orchestrator/orchestrator.go:164-187` and `internal/argocd/client.go:78-82`. `GetRolloutStatus` literally returns `"Healthy"`; the loop treats "no error returned" as Healthy even though `monitorRollout` uses `continue` on errors. Any unhealthy rollout will silently be marked `succeeded` after timeout. Replace with real K8s rollouts client (sig-errored already: client-go) and `time.AfterFunc`-based backoff/cancel. [S] — high.
- [P0] **Reliability** `precheck.Check` has two open `TODO`s at `internal/precheck/precheck.go:34-40`: prod deploys skip user-role verification, and concurrent deploy cap (`maxConcurrentPerEnv:3`) is never enforced (the field is unused). Wire to hamr-account introspection + `SELECT COUNT(*) FROM deployments WHERE status IN ('pending','in_progress')` with row lock — and add a unit test that asserts rejection. [S] — high.
- [P0] **Security** Argo token is read once in `main.go:28` and bound to `argocd.Client{authToken}`; if `ARGOCD_TOKEN` is later set via Vault reload there is no rotation path, and the error returned from `Sync` (`client.go:59`) leaks no status body (lost audit signal). Add structured logging of `sync request_id`, redact token-bearing headers, and surface upstream status text on failure. [S] — med.
- [P0] **Correctness** `GetPreviousSuccessful` (`store/history.go:56-71`) ignores context cancellation and returns `pgx.ErrNoRows` wrapped — but `orchestrator.go:134` checks `prev == nil` against a `*Deployment`, while `err == pgx.ErrNoRows` also returns nil deployment with err. Rollback then fails with `no previous successful deployment found` only sometimes. Normalize: always return `nil, ErrNoPrevious` sentinel and assert on that. [XS] — high.
- [P1] **Performance/observability** `cmd/deploy/main.go:126-131` returns a hand-rolled text/plain `promhttp()` placeholder; the README claims `/metrics` is Prometheus but no metric is registered. Add `prometheus/client_golang`, export request duration + argo sync success counter. [S] — med.
- [P1] **Reliability** `Rollback` is implemented as "re-Deploy with `StrategyRolling`" (`orchestrator.go:138-145`) — losing the original blue-green deploy's audit trail. Should record a `parent_deployment_id` and `trigger_kind='rollback'`. [S] — med.
- [P1] **CLI/UX** No CLI binary entrypoint in `cmd/`; everything is HTTP only. Add a `hamr-deploy deploy --service X --env prod --tag v1 --dry-run` flow that talks to itself's API, so on-call can rollback from a bare kubectl-debug pod. [M] — med.
- [P1] **DX** No `Makefile`/`Taskfile`; Dockerfile copies the whole repo (`Dockerfile:5`) including `migrations/`, `configs/`, `tests/` — bloats context, slows CI cache. Add `.dockerignore` and a `make test|build|lint|run`. [XS] — med.
- [P1] **Deployment** `charts/values.yaml:24` ships the postgres password as a literal Helm value (`postgresPassword: ""`) — even when blank this pattern invites users to commit secrets. Switch to `existingSecret` + external-secrets operator. [XS] — high.
- [P2] **DX/Testing** `tests/orchestrator_test.go` only covers `precheck`; there is no fake `argocd.Client` interface (currently `*argocd.Client` concrete type prevents mocking). Introduce an `ArgoAPI` interface in `internal/argocd`, write golden-file test for full Deploy happy-path. [M] — med.
- [P2] **Performance** `pool, _ := pgxpool.New(...)` in `main.go:32` is missing pool tuning; no `MaxConns`, no `Ping` on startup. Add `cfg.MaxConns=10` + `pool.Ping(ctx)` and surface DB as `not ready`. [XS] — low.
- [P2] **DX** `smoke.sh:36-38` runs `gofmt -e` per file but doesn't run `go vet` or `staticcheck`. Add to Makefile target `make lint`. [XS] — low.

### hamr-jiabu
- [P0] **Privacy** `events.go:65-67` reads `c.GetBool("privacy-store-content")` — this context key is never set anywhere, so the default behavior is to KEEP `event.Content` in the in-memory slice (`h.events`). This directly contradicts `PRIVACY.md` line 18 ("默认丢弃"). Invert default to `event.Content = ""`, make the toggle opt-in via a real middleware + config flag, and document it. [XS] — high.
- [P0] **Persistence** `Handler.events` (`handlers/events.go:24`) is `[]models.InteractionEvent` on the heap — every restart loses all history, every replica of the pod sees only its own slice, and insights computed in `Insights` (`events.go:81-87`) scan the full in-process slice linearly per request. README claims "PostgreSQL" but `go.mod` has no pgx driver. Add a `store.Events` interface backed by Postgres (`migrations/001_create_tables.up.sql`) and an LRU/TTL cache for hot reads. [M] — high.
- [P0] **Agent quality / hallucination guards** The "agent" is a pure rule engine (`detector/rules.go`) but the model abstraction leaks: templates in `suggester/templates.go` use a hash-based stable selection (`hashTrigger`, line 66) which deterministically picks the same template for the same trigger/context — but `TimeAwareContext()` mutates the hash every hour, so users see the suggestion rotate on each poll. Use a counter-based de-dup or a jitter RNG seeded per-thread for variety without churn. [S] — med.
- [P0] **Reliability** `Notify` (`handlers/events.go:111-130`) treats webhook-not-configured as a 200 success with `"reason": err.Error()` — caller can't distinguish "sent" from "no-op". Return 503 and a typed error. Also, no retry queue: a Slack 5xx will silently drop. [S] — med.
- [P0] **Security** `webhook.go:35-54` posts the full request body to whatever URL `SLACK_WEBHOOK` resolves to with no allowlist, no SSRF guard. Pin the domain (or refuse non-HTTPS / non-allowlisted hosts) and reject user-supplied URLs. There is also no `Authorization` header on Slack outbound; many enterprise Slack apps require it. [XS] — high.
- [P1] **Agent quality / eval harness** No golden-file tests for detector rules across edge cases: event timestamps in different timezones, DST boundaries, future-dated events, empty `Content`, multi-byte keyword matches. Convert `rules_test.go` to table-driven and add fixture CSV. [S] — med.
- [P1] **Observability** `main.go:46-49` logs the *masked* URL but never logs the rule engine's triggered counts; no `/metrics`. Add counters `rule_triggered_total{rule}` and webhook outcomes. [XS] — med.
- [P1] **CLI/UX** README promises "POST /v1/jiabu/suggest" endpoint (`README.md:64`) but `main.go:39-41` only registers `events`, `insights`, `notify`. Either remove from README or implement; current docs/code drift will fail smoke tests. [XS] — med.
- [P1] **Privacy** `models.InteractionEvent.Content` (`models/event.go:21`) is sent through gin's `ShouldBindJSON` (max 10MB default) and held in memory unbounded — DoS vector. Cap `Content` length (1KB?), rate-limit `RecordEvent` per `household_id`. [XS] — high.
- [P1] **Configuration** `cmd/agent/main.go:24` hard-codes `notifier.New("", "")` despite env vars loaded at lines 21-22 — webhook URLs are wired but not passed in. Wire `handlers.New(slackURL, emailURL)`. [XS] — high.
- [P2] **Agent cost / token budgets** N/A (no LLM today) but if v0.2 adds LLM summarization, define a budget cap per household/day, log `prompt_tokens`/`completion_tokens`, expose metric. [M] — future.
- [P2] **DX** No `Makefile`; no CI; `Dockerfile` lacks `HEALTHCHECK` directive despite `/health` endpoint. [XS] — low.
- [P2] **Testing** `rules_test.go:73-86` `TestEngineRunsAllRules` doesn't assert on specific rule *triggers*; only `len > 0`. Pin expected triggers for regression safety. [XS] — low.
- [P2] **Reliability** No graceful shutdown drain for in-flight `RecordEvent` handlers (10s grace is fine but `pool.Close` analog absent since no pool). Acceptable for now. [XS] — low.

### hamr-mood-calender
- [P0] **Correctness / agent quality** `trends/trends.go:34-39` groups by `d.Date[:7]` (YYYY-MM, i.e. *month*, not ISO week) but `WeeklyTrend.Week` (`models/mood.go`/struct at `trends.go:11`) advertises weekly, and `insights.Insights` (`trends/insights.go:57-71`) says "较上周" / "较上周下降". Users will see misleading language. Implement ISO week (`time.ISOWeek()` or `date_trunc('week', recorded_date)` in SQL), bucket by week, and surface the correct "本周/上周". [S] — high.
- [P0] **Correctness / persistence** No schema for `household_id` UUID index re-use across services; migration uses UUID but the handler treats it as opaque string. Add `mood_entries.household_id` index aligned with cross-repo shared household service, and a FK to `hamr_account.households(id)`. [XS] — high.
- [P0] **Reliability** `handlers/moods.go:55-58` reads `days := c.Query("days")` but returns 400 *before* parsing it — the read is dead-code. Reads `days` into `_` (the `if d := ... ; d != ""` block has no body after the `{}`). Actual `days` is hard-coded to 30. Fix: parse with `strconv.Atoi`, validate 1..365, pass to store. [XS] — med.
- [P0] **Performance** `store/moods.go:46-69` `ListByMember` and `FamilyDailyAverage` do NOT include `LIMIT`. A member active for years returns every row. Add `LIMIT $3 := 500` or default cap, expose `?days=` with sane range 1..365. [XS] — med.
- [P0] **Performance / indexing** `migrations/...001...up.sql:15-17` has three indexes but no composite `(household_id, recorded_date, mood)` for trends, which scans all rows then groups by date. Add `CREATE INDEX ... (household_id, recorded_date) INCLUDE (mood)` or materialized weekly view. [XS] — high.
- [P1] **Reliability** `Record` (`handlers/moods.go:24-50`) does ON CONFLICT upsert in store but returns the *new* `id` even on update — clients can't tell whether they created or updated. Return `StatusOK` on insert, `StatusOK` with an explicit `updated:true` flag on update, or use `RETURNING (xmax = 0) AS inserted`. [XS] — med.
- [P1] **Time-series data** No backup story (`README.md` only mentions storage). Add `scripts/backup.sh` (`pg_dump mood_entries`) and a documented retention policy (e.g. NDJSON export daily). [S] — med.
- [P1] **Observability** `cmd/server/main.go:42-44` `/health` returns `ok` without DB ping; during DB outage LB will keep routing. Add `pgxpool.Ping` with 1s timeout inside `/health`. [XS] — high.
- [P1] **Security** No auth middleware at all — `householdID := c.GetHeader("X-HamR-Household-Id")` trusts the client. README says "OAuth2 走 hamr-account" but no JWT validation. Add an `auth.Middleware` that validates the bearer token and asserts `c.GetString("household_id") == header`. [M] — high.
- [P1] **CLI/UX** No `/readyz` vs `/livez` separation; K8s `charts/templates/deployment.yaml` defines only `readinessProbe` (and only the legacy `/health`). Split into two probes. [XS] — med.
- [P1] **CLI/UX** `mood` request body validation: `binding:"required,min=1,max=6"` works for int, but handler also calls `req.Mood.Valid()` — duplicate logic. Drop the binding tag and rely on `Valid()` everywhere; or remove `Valid()`. [XS] — low.
- [P1] **Performance** `trends/insights.go:24-25` calls `Weekly` again on every insight request — recomputes the full 56-day scan. Cache for 5–15 minutes per household_id. [S] — med.
- [P2] **DX/Testing** `tests/mood_test.go` has 4 unit tests but no HTTP integration test for `Record`/`Trends`. Add `httptest.NewServer` smoke in CI. [XS] — med.
- [P2] **Performance** `internal/models/mood.go:18-29` builds the emoji/label maps on every call — convert to package-level `var` maps. [XS] — low.
- [P2] **Persistence** No schema-version table (only one migration today). Add `golang-migrate` with `_migrations` table or flyway-style `schema_history` so v0.2 can evolve `mood_entries` without breaking existing rows. [XS] — med.

## Cross-repo opportunities
- **Shared `internal/platform` package** — `hamr-deploy/cmd/deploy/main.go:118`, `hamr-jiabu/cmd/agent/main.go:64`, `hamr-mood-calender/cmd/server/main.go:69` all redefine `getEnv`. Lift to `pkg/hamr/env.go` + `pkg/hamr/server.go` (graceful shutdown) + `pkg/hamr/errors.go` (JSON error envelope: `code`, `message`, `request_id`). Single PR creates 3 small internal packages across 3 go.mod files; reviewed once.
- **Prometheus baseline** — None of the three repos has real metrics; `deploy` ships a placeholder. Centralize `pkg/hamr/metrics.go` exposing `http_requests_total`, `http_request_duration_seconds`, plus per-domain counters (`deployments_total{service,env,status}`, `jiabu_rule_triggered_total{rule}`, `mood_recorded_total{household_id}`).
- **Cross-repo testing utilities** — Each repo has a duplicated `scripts/smoke.sh` with bash + python3 YAML check + gofmt. Replace with `mage` or `task` definitions in a shared `tools/` workspace (path-traversed from a `Makefile` symlink or Go-based `internal/devtools/smoke`).
- **Common Dockerfile** — All three use the same `golang:1.22-alpine → distroless/static-debian12:nonroot` recipe. Promote to a `hamr-go-base` container, parameterize `ENTRYPOINT`. Trim final image by 60-70% (currently copies `go.sum*`, full `configs/`, migrations, charts).
- **Household-ID contract** — `X-HamR-Household-Id` header is parsed in both `jiabu` and `mood-calender` (jiabu: `events.go:37`, mood: `moods.go:26`). Move to shared `pkg/hamr/auth.Middleware` with JWT validation, request_id propagation, and structured logging — fixes two untrusted-header trust issues at once.
- **Webhook notifier extraction** — `jiabu/internal/notifier/webhook.go` is generic Slack/Email POST. `deploy` needs to call Slack on rollback failures and `mood-calender` may want nudges when insights trend negative. Promote `notifier` to shared package.
- **SQL migration runner** — `deploy/migrations/001_create_deployments.up.sql` and `mood-calender/migrations/001_create_mood_entries.up.sql` exist but no tool runs them. Add `cmd/migrate` binary that uses `golang-migrate` (or stdlib pattern). Optional: integrate with initContainer.
- **Helm chart conventions** — Three separate `charts/` with same label conventions (`app.kubernetes.io/name`) and same secret-mount pattern. Promote a `helm-common` library chart with helpers for secretRefs, prometheus scrape annotations, PodDisruptionBudget.

## Top 5 recommended next actions
1. **Fix `monitorRollout` so the success/failure semantics actually match Argo Rollouts state** (`hamr-deploy/internal/orchestrator/orchestrator.go:164-187`, `internal/argocd/client.go:78-82`). Even a stub status from K8s `Rollout` CR would surface real failures. Track as P0 deploy-correctness blocker for v0.2.
2. **Repair `Weekly` grouping to use ISO weeks and align `Insights` deltas to actual weekly comparisons** (`hamr-mood-calender/internal/trends/trends.go:34-39`, `internal/trends/insights.go:57-71`). Currently labels month-over-month as week-over-week — visible bug to end users.
3. **Honor the privacy default in `hamr-jiabu`**: stop relying on a never-set gin context key and flip the default to discard `event.Content` (`events.go:65-67`). P0 privacy/PII risk for a family product.
4. **Extract a shared `pkg/hamr` package for env loading, graceful shutdown, JSON errors, and Prometheus metrics** — every repo reimplements these; one PR yields 3-line savings per service and a single observability surface. Prerequisite for upcoming SLO work.
5. **Wire `notifier.New(slackURL, emailURL)` in `hamr-jiabu/cmd/agent/main.go:24`** and add structured retry/backoff for failed Slack/Email webhooks (`webhook.go:35-77`). Quick win: matches what env vars already imply, unblocks real alerting.

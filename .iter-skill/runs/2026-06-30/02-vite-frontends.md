# Cluster 2: Vite Frontends — Optimization Report
Date: 2026-06-30

## Executive Summary

- Both `hamr-browser` and `hamr-demo` are bare-minimum v0.1 Vite + TypeScript SPAs (no framework, no test coverage, no lint/format, no CI, no observability) — the biggest gap is DX tooling rather than runtime code.
- `hamr-browser` declares PWA + OAuth2 + offline support, but ships **no manifest icons referenced by nginx cache rules, no Service Worker file in `public/` despite the smoke test claiming one, and `sourcemap: true` in production builds**.
- `hamr-demo` ships a hash router that eagerly imports every widget (including `chart.js/auto` ~70KB) on the home page, making the demo's LCP and JS parse cost 5–10× worse than necessary; converting to lazy dynamic imports would cut initial JS by ~80%.
- Cross-repo duplication is severe — both Dockerfiles, nginx configs, charts, `tsconfig.json`, `vite.config.ts`, `smoke.sh`, and Bootstrap CSS imports are nearly identical; extracting a shared base would eliminate ~10 files of drift-prone copies.
- Browser-specific concerns: no `permissions`/`host_permissions`/CSP/security headers in nginx, store-policy-violating wide OAuth scope, and an offline page that claims "cached mood records" exist even though no cache strategy targets `/v1/mood*`.

## Per-repo findings

### hamr-browser

- [P0] **Security — `sourcemap: true` ships source maps to production** — `vite.config.ts:7` — anyone visiting `browser.hamr.top/assets/*.js.map` can read the original TypeScript source, including any future secrets/API shapes baked into the bundle. Switch to `'hidden'` (so they're emitted for error reporting but not linked from JS) or omit in prod. — effort XS — impact high.
- [P0] **Security — missing security headers in nginx** — `nginx.conf` (lines 1-12) — only `X-Frame-Options` and `X-Content-Type-Options` are set; missing `Content-Security-Policy`, `Strict-Transport-Security`, `Referrer-Policy`, `Permissions-Policy`. For an OAuth2-bearing PWA this is mandatory. — effort S — impact high.
- [P0] **Security/Functionality — OAuth2 token in URL fragment is captured but `replaceState` to `/` leaves a stale hash, and `captureTokenFromHash` is never called** — `src/auth/oauth.ts:29-40` and `src/main.ts:10-19` — `bootstrap()` runs `checkAuth()` first; if there's no token it redirects to `#/login`, but `captureTokenFromHash` is never invoked, so the redirect-from-`account.hamr.top` flow will silently fail and bounce users back to login. — effort S — impact high.
- [P0] **Browser-specific — claimed Service Worker file does not exist** — `scripts/smoke.sh:32` requires `public/sw.js` but `public/` only contains `manifest.json`. Either delete the assertion or generate the SW via `vite-plugin-pwa` and verify it lands in `dist/sw.js` (the chart values only nginx-cache `*.js`, not `sw.js`). — effort S — impact high (Chrome Web Store rejects broken offline claims).
- [P0] **Browser-specific — PWA icons referenced from manifest are not in `public/icons/`** — `vite.config.ts:21-22` and `public/manifest.json:11-12` point to `/icons/icon-192.png` and `/icons/icon-512.png`, but the directory does not exist; smoke.sh never checks for them. Browser will fall back, but Lighthouse PWA audit will fail. — effort S — impact med.
- [P1] **Performance — full Bootstrap CSS+Icons imported for ~30KB gz target** — `src/styles/global.css:2-3` pulls entire `bootstrap.min.css` (~25KB gz) and `bootstrap-icons.css` (~30KB gz, of which the app uses ~5 icons). Tree-shake with `bootstrap` JS imports (currently absent, good) and subset icon font. — effort S — impact med.
- [P1] **TypeScript quality — `noUncheckedIndexedAccess` and `noImplicitOverride` not enabled; `experimentalDecorators` enabled without users** — `tsconfig.json:2-13` — strict mode is on but the most valuable `strict`-companion flags (`noUncheckedIndexedAccess`, `noFallthroughCasesInSwitch`, `noImplicitOverride`, `exactOptionalPropertyTypes`) are missing; `experimentalDecorators` is on but nothing in `src/components/*.ts` uses decorators. — effort XS — impact med.
- [P1] **Build/Performance — no code splitting, no lazy routes, `app.innerHTML = handler()` replaces the entire DOM on every nav** — `src/router.ts:26-37` and `src/main.ts:3-7` — every component is bundled together; switching to dynamic `import()` with `await import('./components/hamr-settings')` would let Vite emit per-route chunks and reduce TTI on first paint. Also re-rendering the whole `<main>` destroys focus/scroll position. — effort M — impact high.
- [P1] **DX — no ESLint, no Prettier, no pre-commit hooks** — repo has no `.eslintrc*`, no `.prettierrc*`, no `.husky/`, no `lint` script in `package.json`. With Web Components that mutate `innerHTML` and unchecked `URLSearchParams.get(...)` calls (e.g. `src/auth/oauth.ts:33`), a linter would catch real bugs. — effort S — impact med.
- [P1] **DX — `vite.config.ts` lacks path aliases for `src/` and `vite-plugin-pwa` `injectRegister: 'auto'` not paired with explicit `filename`** — `vite.config.ts:10-46` — `import('@/components/...')` would shorten component imports and survive moves; declaring a custom `manifestFilename`/`registerType` keeps cache busting predictable. — effort XS — impact low.
- [P1] **Observability — no client-side error tracking or web-vitals reporting** — `src/main.ts`, `src/api.ts` — unhandled `ApiError`s bubble to `window.onerror`; there is no Sentry/GlitchTip hook, no `web-vitals` reporter (LCP/CLS/INP), no fetch instrumentation. — effort M — impact high.
- [P1] **Deploy — `package*.json` copy happens before `npm ci`, fine, but `node_modules` is never pruned and there's no `.dockerignore`** — `Dockerfile:3-7` and no `.dockerignore` in repo — `.git`, `.vscode`, `docs/`, `scripts/`, `tests/` (empty) all get copied into the build context, inflating build cache. Final image: `nginx:1.27-alpine` ~40MB + dist; still room for `nginx:1.27-alpine-slim` or distroless. — effort S — impact low.
- [P1] **Deploy — image tag pinned to `latest`, no SHA digest** — `charts/values.yaml:3` — `tag: latest` makes rollbacks impossible and breaks `replicas: 2` for anything other than a deliberately re-tagged build. Switch to `tag: {{ .Chart.AppVersion }}` and pin via image digest in values per-env. — effort XS — impact high (operational).
- [P1] **Browser-specific — `workbox.runtimeCaching` includes `urlPattern: /^https:\/\/api\.hamr\.top\/v1\//` but **no auth header is forwarded** into the cache key** — `vite.config.ts:26-34` — `NetworkFirst` will mix user-A and user-B responses in the same `hamr-api` cache; need a `cacheKeyWillBeUsed` plugin or per-user cache name. **Also a serious privacy bug.** — effort S — impact high.
- [P1] **Browser-specific — `vite-plugin-pwa` is configured but `registerType: 'autoUpdate'` will silently swap code under users mid-session** — `vite.config.ts:11` — for an OAuth2 client this can drop in-flight requests on token boundaries. Use `'prompt'` and show an in-app toast. — effort XS — impact med.
- [P1] **Browser-specific — manifest declares `display: 'standalone'` but no `id` field** — `vite.config.ts:18` — Chrome 108+ requires `id` so PWA updates don't re-install. — effort XS — impact low.
- [P2] **TypeScript quality — `ApiError` class doesn't capture response body cleanly** — `src/api.ts:4-8` — `await res.text()` is awaited twice (once for throw, once lost); store `body` on the instance for diagnostics. — effort XS — impact low.
- [P2] **TypeScript quality — `hamr-tile.ts:7` adds a click listener that always navigates, but custom event semantics are wrong** — `src/components/hamr-tile.ts:5-8` — `connectedCallback` adds a click listener, but `attributeChangedCallback` calls `render()` which **replaces `innerHTML`, removing all child listeners**; the click handler attached in `connectedCallback` lives on the host element, not children, so it works by accident. This is fragile. — effort XS — impact low.
- [P2] **DX — `tests/` is empty despite `test` and `test:e2e` scripts** — `package.json:9-10` declares vitest + playwright, but `tests/` directory is empty (no `.gitkeep`); CI will silently pass with zero tests. — effort S — impact med.
- [P2] **Deploy — `Dockerfile` lacks `HEALTHCHECK`** — `Dockerfile` ends at `EXPOSE 80`; K8s liveness probe in `charts/templates/deployment.yaml:17-19` only does `httpGet /`, which won't detect a wedged nginx. Add `wget --spider` healthcheck inside the image. — effort XS — impact low.
- [P2] **Deploy — no `lifecycle: preStop` hook in deployment.yaml** — `charts/templates/deployment.yaml` — nginx needs `nginx -s quit` to drain in-flight connections; without it, rolling deploys cut TCP. — effort XS — impact low.
- [P2] **Browser-specific — no Content-Security-Policy meta fallback for the SW's intercepted HTML** — `index.html:1-15` — when offline page loads from cache, any CSP must travel via `<meta http-equiv>` since the response is intercepted. — effort S — impact med.
- [P2] **Browser-specific — `manifest.json` `categories: ["lifestyle","productivity"]` and `lang: "zh-CN"` are set, but `dir` and `scope` are missing** — `public/manifest.json` — Chrome Web Store review needs `scope: "/"` to disambiguate PWA from other HamR apps sharing the origin. — effort XS — impact low.

### hamr-demo

- [P0] **Performance — entire bundle is imported on every page load, including `chart.js/auto` (~70KB gz)** — `src/router.ts:1-7` — `renderHome`, `renderMoodDemo` etc. are statically imported, so even visiting `#/` pulls in `chart.js` and the entire `mock/family.ts` (180 entries × 6 members of `MOOD_DATA`). Convert each `renderXxx` to dynamic `() => import('./widgets/mood-demo').then(m => m.renderMoodDemo())`. — effort S — impact high.
- [P0] **TypeScript quality — no `vite.config.ts` plugins, no `build` config** — `vite.config.ts:1-8` (only 8 lines) — no `chunkSizeWarningLimit`, no `rollupOptions.output.manualChunks`, no `cssCodeSplit`. Default chunking is fine for tiny SPAs but no `cssCodeSplit: true` means global.css is one big file. — effort XS — impact low.
- [P0] **Performance — `MOOD_DATA` is generated on every page load (180 entries) but never memoized** — `src/mock/family.ts:33-49` — the loop runs at module init; if chart.js lazy-loads the file lazily, every navigation that touches it re-runs `genMoodData()` because the file is module-cached but the call site is in route listener. Verify it's only called once via `import` (it is — module top-level runs once), so the real fix is making `mock/family.ts` lazy. — effort XS — impact low.
- [P1] **TypeScript quality — same `tsconfig.json` gaps as browser; additionally no `noUnusedLocals`, no `noUnusedParameters`** — `tsconfig.json:1-10` — even less strict than browser (no `isolatedModules`, no `skipLibCheck`). — effort XS — impact med.
- [P1] **Performance — `mood-demo.ts:73` does `location.reload()` on member change** — `src/widgets/mood-demo.ts:73-75` — instead, recompute `labels`/`scores` and `chart.update()`; reloading the whole page destroys the SPA promise. — effort XS — impact med.
- [P1] **Performance — gzip enabled but no Brotli; no `preload`/`prefetch` directives** — `nginx.conf:7-8` — modern browsers prefer `Content-Encoding: br`. Cloudflare in front can negotiate but server should also serve precompressed `.br` if generated. — effort M — impact med.
- [P1] **Performance — no `<link rel="preload">` for `main.ts` or critical CSS** — `index.html:1-19` — first paint waits for parser to discover `<script type="module">`; add `<link rel="modulepreload" href="/src/main.ts">` (Vite emits this automatically if `build.modulePreload: true`, but it's not set). — effort XS — impact med.
- [P1] **Build/Performance — no Brotli/gzip precompression in Vite output** — `vite.config.ts` has no `vite-plugin-compression` or `rollup-plugin-gzip` — runtime compression burns CPU on every request. — effort S — impact med.
- [P1] **Deploy — same Dockerfile as browser (no healthcheck); nginx image lacks version pinning** — `Dockerfile:1-10` — `nginx:1.27-alpine` is OK but `apt/apk` layer caching could be reduced; `HEALTHCHECK` is missing here too. — effort XS — impact low.
- [P1] **Security — OAuth2 curl example in `api-demo.ts:12-15` leaks `client_id`/`client_secret` shape to anyone visiting the demo** — `src/widgets/api-demo.ts:11-16` — even with `<your-*>` placeholders, the surface encourages users to test real credentials in a public widget. Move to `docs.hamr.top`. — effort S — impact high (if ever wired to real creds).
- [P1] **Demo-specific — `random` mood data on every load makes the chart non-deterministic across demos** — `src/mock/family.ts:33-49` — fine for "looks alive", but for a recorded demo tour you want stable seed. Pass an explicit `seed` (or pre-generate once at build time). — effort S — impact med.
- [P1] **Demo-specific — `home.ts` re-implements "card" markup that's a Bootstrap component** — `src/widgets/home.ts:24-39` — uses raw `<a><div class="card">…</div></a>`, which is accessible-fragile (an `<a>` cannot contain block-level elements per HTML spec until `<a>` is restructured in HTML5). Switch to `<a class="card">` or wrap in `<article>`. — effort XS — impact med.
- [P2] **DX — no ESLint/Prettier, no Husky** — same as browser. — effort S — impact med.
- [P2] **DX — no `lint`/`format`/`test` scripts** — `package.json:5-9` only has `dev`/`build`/`preview`. Add `lint`, `format`, `typecheck` (decoupled from `tsc` in `build`). — effort XS — impact low.
- [P2] **Performance — Bootstrap CSS is imported whole; demo only uses `navbar`, `card`, `btn`, `row`/`col`** — `src/styles/global.css:1-2` — subset with PurgeCSS or use Bootstrap's SCSS `@include` to drop ~70% of CSS. — effort S — impact med.
- [P2] **Demo-specific — `jiabu-demo.ts` constructs DOM via `innerHTML` then re-queries after route change** — `src/widgets/jiabu-demo.ts:47-65` — registers a global `route:loaded` listener that adds click handlers via DOM IDs; multiple route visits will stack listeners (memory leak). Use AbortController or `once: true`. — effort S — impact med.
- [P2] **Demo-specific — `home.ts` cards use inline `style="font-size: 64px;"`** — `src/widgets/home.ts:30` — should be a class. — effort XS — impact low.
- [P2] **Demo-specific — no "guided tour" / no Playwright tour** — `scripts/smoke.sh` only validates file existence; no recorded click-through for marketing. Add `tests/e2e/demo.spec.ts` with Playwright to capture screenshots per route. — effort M — impact high.
- [P2] **Demo-specific — `mock/family.ts` has a typo: `mood-calender` (should be `mood-calendar`)** — `src/mock/family.ts:60` — this matches the actual repo name `hamr-mood-calender` in the monorepo, but propagates the typo. If you ever rename the repo, this becomes a phantom reference. — effort XS — impact low.
- [P2] **Deploy — chart `values.yaml` has no `ingress.className`** — `charts/values.yaml:1-12` — but `deployment.yaml:35` references `.Values.ingress.className`; missing key will template to empty. — effort XS — impact med (deploys break).
- [P2] **Deploy — `replicaCount: 2` is hardcoded; staging should be 1** — `charts/values.yaml:4` — split into `values-prod.yaml`/`values-staging.yaml`. — effort XS — impact low.
- [P2] **Security — no CSP header in nginx** — `nginx.conf:1-13` — same finding as browser; demo page is publicly embeddable so iframe-friendly is a feature, but `frame-ancestors *` should be deliberate, not implicit via the default nginx header absence. — effort XS — impact med.

## Cross-repo opportunities

- [P0] **Shared base Dockerfile** — `hamr-browser/Dockerfile` and `hamr-demo/Dockerfile` are 12 and 10 lines respectively with identical structure (node:20-alpine → nginx:1.27-alpine + custom conf). Move to `hamr-infra/docker/vite-base.Dockerfile` and `ARG SERVICE=...` build. Saves ~6 KB of drift-prone copies and makes adding `HEALTHCHECK` a one-liner everywhere. — effort S — impact high.
- [P0] **Shared `nginx.conf` template** — `hamr-browser/nginx.conf` and `hamr-demo/nginx.conf` differ only in caching policy and SW handling. Build a `nginx.conf.template` with `@@SW_POLICY@@` placeholders, or share a common conf + per-service overrides. — effort S — impact med.
- [P0] **Shared `tsconfig.base.json`** — both repos redefine `target`, `module`, `moduleResolution`, `strict`, `lib`; only `isolatedModules`/`useDefineForClassFields`/`skipLibCheck` differ. Promote to `hamr-infra/tsconfig/tsconfig.vite-base.json` referenced via `extends`. — effort XS — impact med.
- [P1] **Shared `vite.config.ts` base** — both have `build.target: 'es2020'` and `build.sourcemap: true`; browser adds PWA plugin. Extract `vite.base.config.ts` with the build target/sourcemap, let each repo add plugins. — effort XS — impact low.
- [P1] **Shared Helm chart template** — `charts/Chart.yaml` and `charts/templates/deployment.yaml` differ only by name; values are also nearly identical. Promote to a library chart at `hamr-infra/charts/vite-spa/` and consume via `dependencies:` in each repo. — effort M — impact high.
- [P1] **Shared `.gitignore`** — both have 5–6 identical lines (dist, node_modules, .vscode, .env, *.log, .DS_Store). Consider a root `.gitignore` or template. — effort XS — impact low.
- [P1] **Shared `smoke.sh` library** — both implement pass/fail logging + required-file lists. Extract `scripts/lib/smoke-common.sh` and let each repo define its own `required=(...)`. — effort S — impact med.
- [P1] **Shared Bootstrap subset** — both `src/styles/global.css` import full Bootstrap CSS+Icons. Move to a shared SCSS file with `@include` of only used modules (reboot, grid, navbar, card, btn, forms). Saves ~150 KB raw CSS in each. — effort M — impact med.
- [P1] **Shared e2e harness (Playwright)** — browser has `@playwright/test` installed, demo has no test infra; add a shared `tests/e2e/` template with a route-load smoke test. — effort M — impact med.
- [P1] **Shared `web-vitals` + Sentry init** — neither repo reports RUM; create `packages/observability` (or a copy-paste snippet) with `reportWebVitals`, fetch instrumentation, and Sentry init guarded by `import.meta.env.PROD`. — effort M — impact high.
- [P2] **Shared `Dockerfile` ignore patterns** — neither repo has `.dockerignore`; add `hamr-infra/templates/dockerignore.vite-spa` with `.git`, `docs/`, `tests/`, `scripts/`, `*.md`. — effort XS — impact low.
- [P2] **Shared API base constant** — `src/api.ts:2` (`hamr-browser`) and (would-be) demo client both hardcode `https://api.hamr.top`. Promote to `@hamr/sdk` package or at least a shared `src/config.ts`. — effort S — impact low.
- [P2] **Cross-repo `TILES`/`SERVICES` registry** — `hamr-browser/src/components/hamr-dashboard.ts:2-16` and `hamr-demo/src/mock/family.ts:51-65` independently list 13 services. Single source of truth at `hamr-infra/services.yaml` consumed by both repos at build time would prevent drift (e.g., the `mood-calender` typo). — effort M — impact med.
- [P2] **Shared OAuth2 helper** — `src/auth/oauth.ts` is browser-only because of `localStorage`; demo never imports it but the curl example recreates the flow. Consider `@hamr/auth` package. — effort M — impact low.

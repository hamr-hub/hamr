# Cluster 3: hamr-browser (Python FastAPI + TS frontend) — Optimization Report (2026-07-01 round 2)
Replaces: .iter-skill/runs/2026-06-30/02-vite-frontends.md (which described PWA only — wrong)

## Executive Summary

- hamr-browser is a **Python 3 / FastAPI / Playwright** service that wraps Playwright flows as an HTTP API, paired with a **Vue 3 + Vite + Tailwind** admin console (`frontend/`) and a 4-file Playwright-based "test harness" (`tests/`) that crawls Amazon UK ASINs and stress-tests the API. Single Chromium persistent-context is shared globally via `BrowserManager`; flows are YAML in `flows/`, secrets in `secrets.yaml`, history is an in-memory deque + JSONL.
- The single biggest gap is **reliability around the shared browser**: only one concurrent flow is allowed by default (`max_concurrent_flows=1`), `launch_persistent_context` is called without an explicit timeout, and "auto-recover" relies on an event callback that re-initializes inside a method that may already hold a lock or be on a closed loop. Several P0 bugs (cookie clear+add race, no CORS, no request-level auth, exposed `/browser/cookies` without auth) are real security/availability risks.
- Other recurring smells: **Jinja2 `Template` rebuilt per render** (no sandbox), **no Pydantic v2 `model_validator` for required params**, **history store grows forever on disk and is never rotated**, **frontend bundles tailwind full but `sourcemap: true` in production**, and **no pytest, no CI, no ruff/mypy/black, no OpenTelemetry, no structured logging**. Recommendations span 5 P0, 8 P1, and 7 P2 findings (20 total).

## Architecture analysis

Verified from code:

- **Process layout** — One FastAPI process (`main.py:1-54`) registered with three routers: `flows` (`app/routes/flows.py:9`), `browser` (`app/routes/browser.py:8`), `logs` (`app/routes/logs.py:5`). `lifespan` (`main.py:13-19`) calls `browser_manager.initialize()` on startup and `close()` on shutdown.
- **Browser management** — `BrowserManager` (`app/browser/manager.py:10-112`) is a process-singleton (`browser_manager = BrowserManager.get_instance()` at module level, line 112). It holds one `playwright.async_api.Playwright` instance and one `BrowserContext` from `chromium.launch_persistent_context(...)` (lines 32-48). Pages are created on demand via `new_page()` (lines 58-64), which attaches a `webdriver` anti-detection init script. Restart re-acquires the lock and re-launches the context.
- **Flow model** — `FlowConfig` (`app/models/flow.py:81-91`) wraps parameters, optional `AuthConfig` (login flow + secrets_key), a list of `Step`s, and a `CaptureConfig` (either `wait_for_response` or `page_evaluate` plus an optional `jsonpath`/`full` extract). Flow YAML lives in `flows/` (`sellersprite_sales.yaml:1-63` is the only shipped example). `FlowStore` (`app/storage/flow_store.py:11-59`) reads/re-parses from disk on every call (no cache).
- **Flow execution** — `run_flow` (`app/engine/flow_engine.py:39-90`) takes a `Semaphore` from `max_concurrent_flows` (default 1), then runs up to 2 attempts (MAX_RETRIES=1, line 26). On any exception other than `CaptureTimeoutError` it calls `browser_manager.restart()` and retries once (lines 62-69). `_execute` (`flow_engine.py:111-157`) opens a page, optionally attaches a `ResponseWaiter` (`app/browser/interceptor.py:14-52`), iterates `flow.steps` via `execute_step` (`app/engine/step_executor.py:23-163`), then awaits the response or runs `page.evaluate` for the capture.
- **Auth handling** — `ensure_logged_in` (`app/engine/auth_checker.py:80-106`) runs `is_logged_in` (`auth_checker.py:12-45`) which navigates + waits 3 s (hard-coded `await page.wait_for_timeout(3000)`, line 27) and matches the URL; if not logged in it runs the YAML-defined login steps with secrets pulled from `secrets.yaml` (`app/utils/secrets.py:12-30`) and rendered through Jinja2 with `{{ _auth.username }}` / `{{ _auth.password }}`.
- **History** — `HistoryStore` (`app/storage/history_store.py:56-92`) keeps a 500-entry `deque` in memory and appends each run to `logs/history.jsonl` (line 66) — no rotation, no read-from-disk on cold start. `list()` walks the deque in Python, returns reversed slice.
- **Frontend** — Vue 3 SPA (`frontend/src/main.ts:1-5`, `App.vue:1-40`) with 5 components (Sidebar/FlowList/FlowDetail/LogList/BrowserStatus). Vite dev-server proxies `/flows`, `/browser`, `/logs`, `/health` to `localhost:8000` (`vite.config.ts:8-13`). API client (`frontend/src/api.ts:87-200`) is a thin `fetch` wrapper. No Pinia, no router, no auth in the UI.
- **Tests/bench** — `tests/stress_test.py` (385 lines) drives the API with a producer/consumer queue + exponential backoff and writes JSONL + JSON report. `tests/crawl_asins.py` (339 lines) uses its own Playwright instance to scrape Amazon UK. `tests/run_test.py` glues the two. There is no `pytest/` and no CI workflow.
- **Container** — `Dockerfile:1-14` extends `mcr.microsoft.com/playwright/python:v1.47.0-jammy` (image is ~1.5 GB), `docker-compose.yml:1-15` mounts `browser_profile`, `flows`, `logs` and binds `secrets.yaml:ro`. `CMD` is `uvicorn main:app --host 0.0.0.0 --port 8000` with no `--workers`, no `--proxy-headers`, no graceful-shutdown timeout.

## Findings

### P0 — Must fix

- **[P0] [Reliability] `BrowserManager._ensure_healthy` is not concurrency-safe and re-inits inside the call path** — `app/browser/manager.py:70-74` — When a flow hits a closed context, `_on_context_close` (line 53) sets `_initialized = False`. The very next call to `new_page()`/`get_context()` (used by *every* flow) will hit `_ensure_healthy`, which calls `initialize()` *without* holding the lock, and `initialize()` itself short-circuits on `self._initialized` (line 26) without the lock — so two concurrent waiters can both pass the check and both call `launch_persistent_context`, double-launching Chromium. Wrap `_ensure_healthy` in the same `self._lock` as `initialize()`, or move the reinit into the close callback. Effort: S. Impact: high.

- **[P0] [Security] `/browser/cookies` and `/browser/{site}/cookies` expose every session cookie to anyone reaching the API** — `app/routes/browser.py:78-103` — `GET /browser/cookies`, `GET /browser/cookies/{site}`, `DELETE /browser/cookies/{site}` are unauthenticated. Combined with the fact that there is no auth on *any* endpoint, anyone on the network can dump and mutate auth cookies for SellerSprite, Amazon, etc. Add a shared bearer token (env `HAMR_API_TOKEN`, `fastapi.Security`) and apply to every router. Also `DELETE /browser/cookies/{site}` (line 94) has a TOCTOU/lost-update race: between `await context.clear_cookies()` (line 99) and `await context.add_cookies(keep)` (line 102) the browser may have closed; switch to `context.clear_cookies(...)` filtered-by-domain, or read cookies, close, then re-add inside one re-entrancy guard. Effort: S. Impact: high.

- **[P0] [Security] No CORS middleware, no rate limiting, and `secrets.yaml` may be served via the YAML upload endpoint** — `main.py:22-39` (no CORS), `app/routes/flows.py:78-103` (POST `/flows` accepts arbitrary YAML and writes it to disk) — An attacker with network access can register a malicious flow that points `capture.script` at `page.evaluate` (`flow_engine.py:139-141`) which runs any JavaScript in the browser context, exfiltrating session cookies. Mitigations: (1) add a token dependency to write endpoints, (2) make `page.evaluate` opt-in or restrict to a YAML allow-list, (3) reject flows that reference file paths outside `flows/`. Effort: S–M. Impact: high.

- **[P0] [Reliability] `launch_persistent_context` has no timeout, so a stuck Chromium hangs the lifespan startup forever** — `app/browser/manager.py:32-48` — `await self._playwright.chromium.launch_persistent_context(...)` is unwrapped; if the Playwright driver crashes or the directory is locked, `/health` (and therefore Docker healthcheck, if added) will never report `ok`. Add an `asyncio.wait_for(..., timeout=30)` wrapper around the launch, log the failure, and surface a 503-style `ready=false` from `/health`. Effort: S. Impact: high.

- **[P0] [Reliability] `run_flow` retry logic restarts the browser inside `MAX_RETRIES=1` then does *not* re-acquire the semaphore, and the `except Exception` swallows `asyncio.CancelledError` on shutdown** — `app/engine/flow_engine.py:61-79` — `except Exception` (line 61) catches `BaseException` subclasses that are *not* safe to swallow; on SIGTERM the in-flight flow will be cancelled, the cancellation is caught and a `FLOW_ERROR` is recorded (line 70-78), then `browser_manager.restart()` is called from a cancelled context which deadlocks. Replace `except Exception` with the standard `except (asyncio.CancelledError,) → re-raise` and `except Exception` chain; gate the `restart` retry on a `not asyncio.current_task().cancelled()` check. Effort: S. Impact: high.

### P1 — Should fix

- **[P1] [Performance] `FlowStore` re-parses every YAML on every request; no in-memory cache** — `app/storage/flow_store.py:16-30, 49-56` — `list_flows()` walks the directory and calls `_load_file` (which does `yaml.safe_load` + Pydantic validation) on every flow on every call. `get_flow` is the same. With N flows the latency is O(N). Add a `dict[str, FlowConfig]` cache invalidated on `save_flow`/`delete_flow` and on a SIGHUP. Effort: S. Impact: med.

- **[P1] [Performance] `execute_step` uses `page.click` / `page.fill` with Playwright's default 30 s timeout, but the surrounding `flow_timeout` is never enforced** — `app/config.py:19` (60 s) and `app/engine/step_executor.py:9, 23-163` (steps use 15 s default but *no* outer deadline) — A flow with 20 steps can run 5 minutes even with `HAMR_FLOW_TIMEOUT=60`. Wrap `_execute` in `asyncio.wait_for(..., timeout=settings.flow_timeout)` and cancel the page on timeout. Effort: S. Impact: med.

- **[P1] [Security] `Template(...).render(**params)` from Jinja2 is not sandboxed; arbitrary attribute access is allowed** — `app/utils/template.py:5-8` — `Template(template_str).render(**params)` instantiates an unsandboxed Jinja2 environment. If a flow author writes `{{ ''.__class__.__mro__[1].__subclasses__() }}` in a step, secrets in the process memory are reachable. Use `from jinja2.sandbox import SandboxedEnvironment; env = SandboxedEnvironment(); env.from_string(template_str).render(**params)`. Effort: XS. Impact: med.

- **[P1] [Security] `secrets.yaml` is mounted `:ro` into the container but is loaded into a process-global mutable dict** — `app/utils/secrets.py:9-30` and `docker-compose.yml:10` — Module-level `_secrets` is global state with no locking; the YAML file is loaded once, and there is no support for hot-reload or file-watching. If the operator edits `secrets.yaml` they must restart the service. Add a `watchfiles` reloader or document the requirement. Also: log a one-line `secrets_loaded: keys=[...]` (not values) at startup so ops can verify. Effort: S. Impact: med.

- **[P1] [Reliability] Hard-coded `page.wait_for_timeout(3000)` in `is_logged_in` and `page.wait_for_timeout(6000)` in the example login flow** — `app/engine/auth_checker.py:27` (3 s) and `flows/sellersprite_sales.yaml:44-45` (6 s) — Both are pure sleeps. The 3 s is on *every* flow run that has auth (login-check), even when cookies are valid and a 100 ms response would suffice. Replace with `page.wait_for_url(pattern, timeout=...)` using the `logged_in_indicator`. Same for the example. Effort: S. Impact: med.

- **[P1] [Frontend] Production build emits sourcemaps and no Content-Security-Policy / CORS** — `frontend/vite.config.ts:15-18` (`sourcemap: true` even in prod), `frontend/index.html:1-13` (no `<meta http-equiv="Content-Security-Policy">`), `main.py:1-54` (no CORS middleware) — Turn off sourcemaps in prod (or use `hidden` source map mode), add `CORSMiddleware(allow_origins=[...])` to `main.py`, and add a strict CSP to `index.html`. Also: the frontend `BASE_URL` in `frontend/src/api.ts:7` is `http://localhost:8000` even in production — it must be configurable via `VITE_API_BASE`. Effort: S. Impact: med.

- **[P1] [DX] No `pyproject.toml`, no `ruff`/`mypy`/`black` config, no CI workflow** — Repo root has only `requirements.txt`, `Dockerfile`, `docker-compose.yml` and `.gitignore`. `tests/` contains three ad-hoc scripts, not `pytest`-discoverable tests. Add: `pyproject.toml` (with `[tool.ruff]`, `[tool.mypy]`, `[tool.pytest.ini_options]`), `pytest` tests covering `flow_engine`, `flow_store`, `template`, `secrets`, `auth_checker` with mocked Playwright, and a `.github/workflows/ci.yml` that runs `ruff check`, `mypy`, `pytest`, then builds the frontend and the Docker image. Effort: M. Impact: med.

- **[P1] [Observability] Logs go to `run.log` in the same `logs_dir` mount and have no structured fields** — `app/utils/logger.py:1-19` — `format="%(asctime)s [%(levelname)s] %(name)s: %(message)s"` is human-readable only; there's no `run_id`, no `flow_id`, no JSON. Switch to `structlog` with JSON renderer, add `extra={"run_id": ..., "flow_id": ...}` to all engine logs, and emit OpenTelemetry spans (or at least Prometheus counters: `flows_total{status}`, `flow_duration_ms`, `browser_restarts_total`) from `flow_engine`. Effort: M. Impact: med.

### P2 — Nice to have

- **[P2] [Performance] `HistoryStore.list()` builds Python lists and reverses on every call** — `app/storage/history_store.py:70-83` — For 500 records this is fine, but with JSONL persistence the natural move is to keep an in-memory BTree keyed by `run_id` (already O(1) via the `get` linear scan, line 85-89 — fix that too) and append-only file. Replace `get()` linear scan with a dict. Effort: S. Impact: low.

- **[P2] [Reliability] `history.jsonl` is appended to in `HistoryStore.add` (`history_store.py:64-68`) inside an unawaited blocking `open(... "a")` from a thread-pool-less async path** — `app/storage/history_store.py:65-66` — `aiofiles` is in `requirements.txt:9` but not used here; the sync `open` blocks the event loop on disk stalls. Either use `await aiofiles.open(...)` or move the append to a `asyncio.to_thread` call. Effort: S. Impact: low.

- **[P2] [Deploy] Playwright base image is `v1.47.0-jammy` (Ubuntu 22.04) and is not pinned to a digest** — `Dockerfile:1` — Pin to a specific SHA digest, and add a `HEALTHCHECK` directive (`HEALTHCHECK --interval=30s --timeout=5s CMD curl -fsS http://localhost:8000/health || exit 1`) so compose's `restart: unless-stopped` plus an orchestrator can detect dead instances. Also multi-stage-build a smaller runtime (the chromium binary is ~300 MB). Effort: M. Impact: low.

- **[P2] [Security] `secrets.yaml` filename is hard-coded as the default but the code path also accepts the env var** — `app/config.py:15` and `app/utils/secrets.py:17-21` — If `secrets.yaml` is missing, a `WARNING` is logged and an empty dict is cached; the service then continues to advertise login support via `flow.auth` but every login fails silently. Add a startup check that fails fast if any flow has `secrets_key` set but the file is missing/invalid. Effort: XS. Impact: low.

- **[P2] [Frontend] `BrowserStatus.vue` `loadLoginStatuses` fires one `checkLoginStatus` per flow with no abort/debounce** — `frontend/src/components/BrowserStatus.vue:213-227` — `Promise.allSettled(flows.map(...))` will hammer the backend when flows scale. Add a debounce, and a `try/catch` per flow (the current code only catches the outer `getFlows` failure). Effort: XS. Impact: low.

- **[P2] [Frontend] `App.vue` keeps `selectedFlowId` in a `ref` and shows `<FlowDetail :flow-id="selectedFlowId!" />` with a non-null assertion** — `frontend/src/App.vue:14-16, 34-39` — Vue's `!` non-null assertion will not help in production builds (TS-only); use a v-if guard. Also: the active view state is a string union, not a router — add `vue-router` once there are 4+ views. Effort: S. Impact: low.

- **[P2] [DX] `tests/stress_test.py` and `tests/crawl_asins.py` are not part of `pytest` discovery and have no `__init__.py` in `tests/`** — `tests/` directory listing shows only `.py` scripts and a `data/` folder. Add `tests/__init__.py`, convert the ad-hoc scripts into `pytest` parametrized tests (using `pytest-asyncio` + `httpx.AsyncClient(transport=ASGITransport(app=app))` so they don't need a live server), and move `data/` under `tests/fixtures/`. Effort: M. Impact: low.

## Top 5 recommended next actions

1. **Add an API token dependency and apply to every router** (P0 #2) — One-line `Depends(bearer_auth)` on each router, plus `CORSMiddleware`. Closes the unauthenticated `/browser/cookies` exfil path and the malicious-flow upload path in a single change. Effort: S.
2. **Make `BrowserManager.initialize` and `_ensure_healthy` re-entrancy-safe** (P0 #1) — Wrap both in `self._lock`; add a `asyncio.wait_for(launch_persistent_context, 30)` deadline. Effort: S.
3. **Enforce `flow_timeout` and `CancelledError` correctness in `flow_engine.run_flow`** (P0 #5 + P1 #2) — `asyncio.wait_for(...)` around `_execute`, re-raise `asyncio.CancelledError`, and gate the `restart` retry on cancellation status. Effort: S.
4. **Sandbox Jinja2 templates and add Pydantic validators to `FlowConfig`** (P1 #3 + P1 #6) — `SandboxedEnvironment` in `template.py`; a `model_validator` on `FlowConfig` rejecting flows with `capture.type == "page_evaluate"` by default. Effort: S–M.
5. **Add `pyproject.toml` + ruff/mypy/pytest + a CI workflow** (P1 #7) — Single PR unblocks a long tail of lint and test debt. Effort: M.

## Executive Summary

- **`hamr-app` ships an auth-MIDDLEWARE PLACEHOLDER** (`repos/hamr-app/backend/src/middleware.rs:37-46`) that injects a hard-coded `Claims::default()` regardless of any token — every device-DID-protected endpoint is currently wide open to any caller that can reach port 3002. This is a P0 critical finding.
- **Refresh-token verification is an O(N) bcrypt brute-force over up to 100 active rows on every `/auth/refresh` call** (`repos/hamr-account/backend/src/handlers/auth.rs:90-100`); on a cold DB with 1k+ tokens each request costs ≥100 × bcrypt-cost. Replace with opaque random refresh-token rows hashed with SHA-256 (the bcrypt step is on top of an already 32-byte-random token → no defensive value).
- **`hamr-api` exposes `jwt_secret = "dev-secret-change-in-production"` as the fallback default** (`repos/hamr-api/src/config.rs:19`) — defaults of unsafe values bypass every DEPLOY.md instruction once the env var is missed.
- **No graceful shutdown / SIGTERM / `with_graceful_shutdown`** in any of the 5 backends; P2P node (`p2p.rs`) and DB pools (PgPool/SqlitePool) drop on stop signal without draining.
- **No tests, no clippy config, no CI workflow in any backend submodule** (verified via `find repos -name tests -o -name .github`). Cargo.lock is committed in only hamr-api and hamr-app but the other 3 don't pin — release builds will float.

## Per-repo findings

### hamr-account

- **[P0] Security — JWT secret has insecure default fallback** — `repos/hamr-account/backend/src/config.rs:20-21` — `unwrap_or_else(|_| "default-secret-change-in-production".to_string())` — there is no `.context()` / `anyhow::bail!` to fail closed. The exact string will be hot-patched in many deployments. **Effort XS / Impact CRITICAL.** Fix: `let jwt_secret = std::env::var("JWT_SECRET").context("JWT_SECRET must be set")?;`.
- **[P0] Security — Refresh-token verification does bcrypt on every active token in DB** — `repos/hamr-account/backend/src/handlers/auth.rs:90-100` (`/auth/refresh`) and `:127-141` (`/auth/logout`) — query loads up to 100 rows then runs `bcrypt::verify` per row. Cost is 100 × ~100ms = 10s on a hot hash at default cost (12). Attack vector: high-velocity /refresh spamming burns CPU. **Effort S / Impact HIGH.** Fix: store SHA-256(refresh_token) and equality-compare; keep bcrypt only for passwords.
- **[P0] Reliability — No graceful shutdown on `tokio::net::TcpListener`** — `repos/hamr-account/backend/src/main.rs:38-39` — `axum::serve(listener, app).await?` with no signal handler. On `docker stop` (15 s grace) the process dies mid-request; refresh-token INSERTs in flight get partial commits. **Effort XS / Impact MED.** Wrap with `axum::serve(listener, app).with_graceful_shutdown(shutdown_signal())`.
- **[P1] Performance — `PgPool::connect` without `PgPoolOptions::new().max_connections(...)`** — `repos/hamr-account/backend/src/db.rs:12` — defaults to 10 connections, but the app also embeds bcrypt CPU work synchronously inside the request tokio task → refcount will starve under login-storm. **Effort XS / Impact MED.** Set explicit `max_connections(20)` + `min_connections(2)` + `acquire_timeout`, and run bcrypt via `tokio::task::spawn_blocking` (currently `bcrypt::hash(DEFAULT_COST)` blocks the reactor at `handlers/auth.rs:37`, `:67`, `:179`).
- **[P1] Security — Invite-code generator yields only 16^8 ≈ 4.3 × 10^9 combinations** — `repos/hamr-account/backend/src/handlers/family.rs:234-238` — but generates from `Uuid::new_v4()` first 8 hex chars (uppercased, hyphens stripped) → effectively 16^8 = 4.29B; with rate-limit at gateway (60/min) brute-force is impractical today but the unique-constraint rescue means each collision = DB round-trip. **Effort XS / Impact LOW.** Document risk + add length to 10; or move to `rand::distributions::Alphanumeric` 12 chars for ~68 bits entropy.
- **[P1] Security — `family.get_my_families` SQL swallows errors silently then returns a degraded view** — `repos/hamr-account/backend/src/handlers/family.rs:69-95` — the `match rows { Err(_) => … }` block returns `member_count = 0` if the GROUP BY query fails for ANY reason (e.g. timeout, partial outage). Hides 500s from observability. **Effort XS / Impact MED.** Log `error!` and propagate.
- **[P1] Security — Password-validation only enforced length 8, no complexity or breached-list check** — `repos/hamr-account/backend/src/handlers/auth.rs:19-23` and `:54-58`. Local weak passwords (`password123`) are accepted. **Effort S / Impact MED.** Combine with `validator` crate (already in deps `Cargo.toml:21`) and zxcvbn / haveibeenpwned API.
- **[P1] Security — Request body size not limited on registration/login/refresh** — `repos/hamr-account/backend/src/main.rs:30-32` and `routes.rs:13-40` — no `tower_http::limit::RequestBodyLimitLayer`. With `axum::Json` and `axum::body::to_bytes` defaults to 2 MB but no global cap. Combined with bcrypt, an attacker can DoS. **Effort XS / Impact MED.** Add `RequestBodyLimitLayer::new(64 * 1024)` (auth is small) + per-handler overrides.
- **[P2] Observability — `tracing_subscriber::fmt::init()` is unstructured text** — `repos/hamr-account/backend/src/main.rs:18`. Use hamr-api's JSON pattern with `RUST_LOG` filter (`repos/hamr-api/src/main.rs:15-21`) for uniform log shipping.
- **[P2] Deps — No `Cargo.lock` committed** — `repos/hamr-account/backend/Cargo.lock` does not exist. Builds will float. **Effort XS / Impact MED.** `cargo generate-lockfile` then commit.
- **[P2] CI/DX — No GitHub Actions, no clippy/fmt/deny config.** **Effort M / Impact MED.** Add `.github/workflows/rust.yml` with `cargo clippy -- -D warnings`, `cargo fmt --check`, `cargo deny check advisories`, `cargo audit`.
- **[P2] Auth-Z — No email verification enforced despite `email_verified` column** — `repos/hamr-account/backend/migrations/20260310000001_init.sql:10`, `:44` — flag is set but is never checked anywhere (`handlers/auth.rs:61-67`). **Effort S / Impact MED.**

### hamr-api

- **[P0] Security — Insecure default `jwt_secret` and service URLs hardcoded** — `repos/hamr-api/src/config.rs:19-26` — every default is a known string. If `JWT_SECRET` env var is forgotten, anyone reading the repo can forge tokens for any user. **Effort XS / Impact CRITICAL.** Make required; remove defaults.
- **[P0] Security — `CorsLayer::new().allow_origin(Any)` on a public-internet gateway** — `repos/hamr-api/src/main.rs:29-32` and `/api/v1/account/*` flows. **Any** website the user visits can issue authenticated requests against logged-in browser. Combined with token-from-localStorage pattern in `frontend/src/store.ts:36` this is full account takeover XSRF. **Effort XS / Impact CRITICAL.** Switch to the allow-list pattern already present in hamr-account's `build_cors_layer` and require `ALLOWED_ORIGINS`.
- **[P0] Reliability — Hard-coded `reqwest::Client` 30 s timeout, no retry/backoff, no per-target circuit breaker** — `repos/hamr-api/src/proxy.rs:14-20` and `:82-99` — a transient downstream hiccup yields 502 to the client AND no metric granularity beyond the request counter. **Effort M / Impact HIGH.** Split the `OnceLock` into 3 `Client`s (one per backend) and add `tower::ServiceBuilder` retry or `backoff`. Even better, use `tower` service stack.
- **[P0] Security — Rate limiter is a process-local `DashMap`, not shared across replicas** — `repos/hamr-api/src/middleware.rs:23-51` — key `x-forwarded-for` is also client-spoofable without a real proxy chain. With the gateway being horizontally scaled, limits = `limit × replicas`. **Effort M / Impact HIGH.** Either (a) trust only the leftmost X-Forwarded-For value via the LB stripping, or (b) move to `tower-governor` with a Redis backend.
- **[P0] Security — Rate limiter key defaults to `"unknown"` for any request without `x-forwarded-for` AND falls back to a single shared bucket** — `repos/hamr-api/src/middleware.rs:85-91` — when the gateway is hit directly (e.g. internal calls), all traffic shares one 60-rpm budget. **Effort XS / Impact HIGH.** Use the auth `sub` claim once authenticated, else the real IP from a configured `TRUSTED_PROXY_HEADER`.
- **[P1] Performance — `proxy.rs` reads request body into memory up to 10 MB before forwarding** — `repos/hamr-api/src/proxy.rs:94-97` — `axum::body::to_bytes(..., 10 * 1024 * 1024)` collects the entire body, then `req.body(body).send()` re-encodes. Should stream with `reqwest::Body::wrap_stream`. **Effort M / Impact MED.**
- **[P1] Performance — `metrics_middleware` does a per-request `path.to_string()` clone + `normalize_path`** — `repos/hamr-api/src/metrics.rs:23-25`, `:76-86` — fine for low-volume but cardinality-safe only because normalize clips 3 paths. The `client_ip` string allocation happens even on `/metrics` and `/health` which inflates the request_labels. **Effort S / Impact LOW.**
- **[P1] Observability — Tracing is JSON but logs every request at `info` level regardless of status** — `repos/hamr-api/src/metrics.rs:64-71` — successful 2xx and 5xx both log at info. Should demote healthy 2xx to debug. **Effort XS / Impact LOW.**
- **[P1] Security — Proxy `request.headers().clone()` forwards `authorization`, `cookie`, `cf-connecting-ip`, etc. without scrubbing** — `repos/hamr-api/src/proxy.rs:32-36` — the source backend will see the *gateway's* `host` and a forwarded Authorization that was decoded (or forged) upstream. **Effort XS / Impact MED.** Maintain an explicit allowlist (`content-type`, `accept`, `accept-language`, `user-agent`, `x-request-id`).
- **[P2] API design — No OpenAPI/Swagger spec, no `utoipa`** — endpoints are in `routes.rs:19-43`. **Effort M / Impact MED.** Add `utoipa` with `#[derive(ToSchema)]` on `Claims` and document operation IDs; emit `GET /api-docs/openapi.json`.
- **[P2] Reliability — `/health` is a static 200 OK** — `repos/hamr-api/src/routes.rs:45-51` — should verify downstream services reachable + DB pool not exhausted. **Effort M / Impact MED.**
- **[P2] Deps — No CI/lint** (no `.github/workflows`, no `.cargo/config.toml`). **Effort M / Impact LOW.**

### hamr-app

- **[P0] Security — `auth_middleware` is a placeholder that injects `Claims::default()` for ANY caller** — `repos/hamr-app/backend/src/middleware.rs:37-46` — **the entire API is unauthenticated today**. Anyone reachable on port 3002 can `GET/POST/PUT/DELETE` people/events/tasks/things/spaces for ANY family_id. **Effort M / Impact CRITICAL.** Implement Phase 2: parse `Authorization: Bearer <DID-signed-token>`, verify ed25519 signature (using `DeviceIdentity::verify` from `did.rs:75-89`), look up device DID, attach `Claims`.
- **[P0] Security — Handlers ignore `Claims` (`let _ = claims;`) and trust the `family_id` from the URL** — `repos/hamr-app/backend/src/handlers/people.rs:13`, `events.rs:9`, `tasks.rs:10`, `things.rs:10`, `spaces.rs:10`, `dashboard.rs:11` — there is NO row-level security: any caller can pass any `family_id` and read/write. **Effort M / Impact CRITICAL.** Introduce a `device→family` mapping table and check it server-side.
- **[P0] Security — Device private key persisted to `~/.hamr/identity.json` in plaintext JSON** — `repos/hamr-app/backend/src/did.rs:108-130` (`save`). File mode bits not set; on a multi-user host the key is world-readable. **Effort S / Impact HIGH.** Use `secrecy::SecretVec` + `argon2`/`chacha20poly1305` derived from an OS keystore, or `keyring` crate; ensure `0600` on Unix.
- **[P0] Security — `tracing::info!("Loaded device identity from {:?}", path)` logs the full file path and `tracing::info!("... signature ...", peer_id)` logs peer_ids over plaintext** — `repos/hamr-app/backend/src/did.rs:97-99`, `p2p.rs:319-323`. PII/PHI leakage in log aggregation if family names ever join IDs. **Effort XS / Impact MED.** Hash or redact before log.
- **[P0] Reliability — P2P `handle_incoming_sync` is a TODO and currently a no-op** — `repos/hamr-app/backend/src/p2p.rs:505-515` — the entire gossipsub sync path is dead code. The README and routes claim sync but data is per-device only. This is product-correctness, not just code health. **Effort L / Impact CRITICAL for product.**
- **[P1] Performance — `dashboard::get_stats` issues 5 sequential SQL round-trips** — `repos/hamr-app/backend/src/handlers/dashboard.rs:15-35` — each `fetch_one` is a separate round-trip. Bundle into a single SELECT with CASE/sum or pg's `(SELECT ...) UNION ALL`. **Effort S / Impact MED.**
- **[P1] Performance — `family_id` is passed as a query string and read out of `HashMap<String, String>`** — every handler (`people.rs:10`, `events.rs:11`, `tasks.rs:11`, `things.rs:11`, `spaces.rs:11`) re-parses. Switch to a typed extractor `Query<FamilyIdQuery>` with `Option<Uuid>`. **Effort XS / Impact LOW.**
- **[P1] Performance — `Pagination` cap is hardcoded in models.rs:241** — `min(100)` per page is reasonable, but the handler list endpoints lack any pagination and will return ALL rows for a family. **Effort S / Impact MED.** Pass `Query<Pagination>` and `LIMIT/OFFSET`.
- **[P1] Security — `tag` is `TEXT[]` Postgres array; `register` accepts any tag list with no allow-list** — `repos/hamr-app/migrations/20260310000001_init.sql:15` and `models.rs:33` — tag flood by untrusted family. **Effort XS / Impact LOW.**
- **[P1] Performance — `tracing_subscriber::fmt::init()` plain-text logs, no JSON for prod** — `repos/hamr-app/backend/src/main.rs:25` — same as hamr-account; inconsistent with hamr-api.
- **[P1] Reliability — SQLite at `~/.hamr/hamr.db` not set to WAL mode, no busy timeout** — `repos/hamr-app/backend/src/db.rs:21` — `SqlitePool::connect` defaults to journal=DELETE; concurrent writes (multi-handler) can hit SQLITE_BUSY under load. **Effort XS / Impact MED.** `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000;` on connect.
- **[P2] Deps — `Cargo.lock` IS committed** here ✅, but CI is still missing.
- **[P2] Frontend — `axios.create` with `baseURL: http://localhost:3002` hardcoded fallback** — `repos/hamr-app/frontend/src/api.ts:3` — if `VITE_API_URL` is missing in production build, app will only work locally. **Effort XS / Impact MED.**
- **[P2] Frontend — Token stored in `localStorage`** — `repos/hamr-app/frontend/src/api.ts:11` — XSS-vulnerable (no `httpOnly` cookie) but currently moot because the backend doesn't validate the token at all.
- **[P2] Frontend — No CSP headers in nginx.conf** — `repos/hamr-app/frontend/nginx.conf`. Add `add_header Content-Security-Policy "default-src 'self'; connect-src 'self' https://app.hamr.store; ..."`.
- **[P2] DX — `package.json` includes `framer-motion` and `date-fns`** — adds 100 kB; consider `motion` (smaller) and native `Intl.DateTimeFormat`.

## Cross-repo opportunities

1. **Shared JWT lib** — All 3 backend services (account/jiabu/api) re-implement `Claims::decode` with `jsonwebtoken::decode + Validation::default()`. Hoist into a `hamr-auth` crate shared via a workspace at the top repo. Also fixes the interop default (`dev-secret` vs `dev-secret-change-in-production` vs `default-secret-change-in-production`). **Effort M / Impact HIGH.**
2. **Shared CORS module** — `CorsLayer::new().allow_origin(Any)` appears in 3 of 5 main files; hamr-account's `build_cors_layer` is the only allow-listed variant. Reuse. **Effort XS / Impact CRITICAL.**
3. **Shared error/log types** — 4 of 5 apps duplicate `AppError` + `IntoResponse`. Hoist. **Effort S.**
4. **Consistent tracing setup** — 4 services, 4 different `tracing_subscriber::fmt::init()` invocations (hamr-account plain, hamr-api JSON, hamr-app plain, hamr-jiabu plain, hamr-demo registry). Use hamr-api's JSON pattern uniformly + add `tracing-bunyan-formatter` for production log shipping. **Effort S / Impact MED.**
5. **Workspace `Cargo.toml`** — Promoting the 5 backends to a single Cargo workspace enables shared dev-deps (`proptest`, `criterion`, `wiremock`, `testcontainers`), shared `cargo deny` config, and shared CI matrix. The current per-repo independent structure makes consistent lints nearly impossible. **Effort M / Impact HIGH.**
6. **Distroless final image** — All 5 Dockerfiles use `debian:bookworm-slim` final stage (`repos/hamr-*/Dockerfile`). Switching to `gcr.io/distroless/cc-debian12` saves ~140 MB per image and removes shell attack surface. **Effort S / Impact MED.**
7. **Connection-pool tuning** — Only hamr-api (no DB) and hamr-demo (no DB) don't need it; the other 3 must specify `PgPoolOptions::new().max_connections(20).min_connections(2).acquire_timeout(Duration::from_secs(2))`. Currently only hamr-jiabu sets `max_connections(10)` (`db.rs:13`).
8. **Graceful shutdown** — All 5 main loops `axum::serve(listener, app).await?` with no signal handler. Add `tokio::signal::ctrl_c()` + `with_graceful_shutdown(...)`. **Effort S per service / Impact HIGH.**
9. **No test infrastructure** — No `tests/` in any submodule, no `#[cfg(test)]` except hamr-app's `did.rs`. Add integration tests with `sqlx::test` + a shared `docker compose.test.yml` for Postgres 16. **Effort L / Impact HIGH.**
10. **No CI** — No `.github/workflows/` in any submodule. **Effort M / Impact HIGH.** (Note: `repos/hamr-browser/tests` exists but is frontend.)
11. **Frontend `localStorage` token pattern** — All 4 full-stack services do this (`hamr-account/frontend/src/api.ts:11`, `hamr-app/frontend/src/api.ts:11`). Should move to `httpOnly; Secure; SameSite=Lax` cookies + CSRF tokens; or at least add `crypto.subtle`-encrypted storage. **Effort M / Impact HIGH (XSS).**
